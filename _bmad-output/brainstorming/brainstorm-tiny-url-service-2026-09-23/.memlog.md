- (direction) Clean-slate tiny URL service; prior similar services must not influence the design
- (decision) Stance is Creative Partner
- (decision) Order: 1 Backcasting, 2 Vocabulary Exile (invented), 3 Swarm Logic (chosen)
- (technique) invented Vocabulary Exile: ban the words link, URL, short, redirect, click, and code; describe the service only in the language of a trade that has never touched the web, throw out any idea that needs a banned word, then allow one banned word back and see what survives
- (decision) Chosen Swarm Logic (biomimetic): forbid the master plan; solve with dumb local rules so order emerges from the bottom up. Fits because it blocks the usual central shortener design
- (technique) started Backcasting
- (idea by coach) 2031 night market: a stamp-sized paper slip with no readable letters; a tap puts the customer inside last week's exact dish, price already agreed, vendor greeting them by the name from that night; slips come off a morning roll; after a flood moves the stall, old slips still find it
- (idea by user) Keep the slip and the information related to it
- (idea by coach) The slip is like a banknote: two slips from the same roll are strangers. Fused to each scrap are three facts — who tore it, what they meant in that moment, and the rule for what still counts as the same meaning after the world moves
- (direction) Redirect focus: merchant creates a tiny URL from this service; the tiny URL sends the customer to a long URL that contains the order information
- (idea by user) Merchant provides a tiny URL, created by this service, that sends the customer to a long URL containing the order information
- (idea by coach) Finished moment: merchant asks the service for a tiny URL and puts only that on the slip; the customer arrives at a long URL that already holds the order
- (idea by user) Merchant provides a long complicated URL found by navigating their customer order site
- (idea by coach) The service never learns what an order is. It only takes the address the merchant copied from their order site and returns a tiny URL small enough for the slip. The customer lands on that same order page
- (idea by user) Angry if the customer lands on a page that does not have their specific order
- (idea by coach) The tiny URL is only good if it keeps the exact part of the long URL that names this one order. Dropping that part is the failure
- (idea by user) Before the customer uses it, the tiny URL must already have been created, and it must be unique, idempotent, and persistent
- (idea by coach) The same long order address, asked for twice, returns the same tiny URL, and that tiny URL still opens that exact order later. A different order never receives it
- (idea by user) The service must check if it exists first, and the write must be atomic so wrong data cannot be stored when generating the tiny URL
- (idea by coach) The check is on the long order address. If it is already stored, the existing tiny URL comes back and nothing new is written. If it is not, the tiny URL and that exact long URL are written together or not at all. A second request in the same instant cannot bind a different order to that tiny URL
- (idea by user) Persistence layer must be in place, plus logic to sanitize the input and double-check the business rules for creating a tiny URL from a long URL
- (idea by coach) The raw address is sanitized before the existence check, so two messy copies of the same order address count as the same one. A rule-breaking address never reaches the store
- (idea by user) Business rule: the long URL must exist so a mistaken long URL is not added
- (idea by coach) The service fetches the long URL before any write. A real page has to come back or nothing is stored, and the merchant still holds the mistake
- (idea by user) A valid HTTP success response is required before minting. Most or all 400 errors, such as 404, are not valid
- (idea by coach) A 2xx is the only ticket into the atomic write. A 404 and the other mistake-status responses are refused, nothing is stored, and the merchant sees the status
- (idea by user) A redirect that reaches the order counts as success
- (idea by coach) The hop proves the address is alive. The tiny URL keeps the exact long URL the merchant pasted, so the customer still follows the path the merchant chose
- (idea by user) Keep the original URL the merchant pasted, even if a redirect hop would land on a different order
- (idea by coach) First move: a store that, given a cleaned original long URL, returns the tiny URL already bound to it, or atomically binds a new unique tiny URL to that exact original string. The success check happens before that act
- (decision by user) The first move is the store: given a cleaned original long URL, return the tiny URL already bound to it, or atomically bind a new unique tiny URL to that exact original string. The success check happens before that act
- (technique) started Vocabulary Exile
- (idea by coach) Vocabulary Exile lens: a cloakroom. Merchant brings a long note naming one coat. Attendant confirms the coat is hanging, follows a curtain into the right aisle if needed, files the original note with a brass disc together or not at all, and the same note always gets the same disc
- (idea by user) The service should be a seamless way for a complex destination to be easily available using a digital device connected to the web
- (idea by coach) The customer never handles the long note. Their device takes the brass disc in one motion and the coat is simply there. The merchant did the hard walk once. The customer does none of it
- (idea by user) It is a digital address. The customer is spared the complexity
- (idea by coach) The digital address is all the customer ever holds. The tangled note stays in the ledger, and the address does not grow when the note gets more tangled
- (idea by user) Any other info must never show up in the digital address
- (idea by coach) The address is mute. A stranger who sees the disc learns nothing about the coat, the aisle, or the order. The ledger is the only place the note can be read
- (idea by user) The merchant is allowed to see the content of the disc
- (idea by coach) When the attendant hands back the disc, the merchant is also shown the note that was filed with it. A stranger who only finds the disc later sees the mute stamp and nothing of the coat
- (decision) Leave Vocabulary Exile; move to Swarm Logic
- (technique) started Swarm Logic
- (idea by coach) No master map. Four local rules only: (1) a messy note is cleaned before anyone looks it up, (2) a note that fails the alive-check is refused and nothing is filed, (3) the same cleaned note always gets the same disc, (4) a new disc and its note are filed together or not at all. Order comes from following those, not from a central design
- (direction) User ready to leave Swarm Logic / end the technique batch without adding a fifth concurrency rule
- (decision) Technique batch complete: Backcasting, Vocabulary Exile, Swarm Logic
- (insight) User affirms the mirror: the kept ideas are the ones that matter. Themes: merchant-minted mute digital address for order-site destinations; exact original long URL preserved; unique+idempotent+persistent via sanitize then alive-check then atomic bind; first move is that store. Links: wrong-order anger and mute address are one guarantee (identity without leakage); cloakroom disc/note is the store bind in different clothes; four swarm rules are the same pipeline as backcasting's first move
